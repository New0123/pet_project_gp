================================================================================
gp_from_parquet.py — загрузка parquet-файлов в Greenplum
================================================================================

Файл скрипта:  /home/имя_папки_проекта/gp_from_parquet.py
Отчёт:         /home/имя_папки_проекта/parq_exp_resume.txt
Подключение:   /home/имя_папки_проекта/.env.secret_db (блок GP_IN_*)

Скрипт читает один parquet-файл или все файлы по маске, при необходимости
фильтрует и сортирует данные, затем грузит их в таблицу Greenplum через
COPY ... FROM STDIN порциями (после каждой порции — COMMIT).


ЗАПУСК
------

    cd /home/имя_папки_проекта

    ./gp_from_parquet.py <файл|маска> <схема> <таблица> [batch_size] [опции]

Параметры можно задавать и в форме key=value (порядок не важен):

    ./gp_from_parquet.py source=/path/exp_*.parquet schema=exp_schema table=tbl
    ./gp_from_parquet.py source="exp_*.parquet" schema=exp_schema table=t \
        batch_size=10000 where="rrrr_name='7777777777'" order_by=rrrr_key

Поддерживаются ключи: source (file, filename), schema, table, batch_size
(batch-size, batch), order_by (order-by), where, limit. Остальные опции
(--truncate, --dry-run и т.д.) — как обычно.

Параметры:

  source          имя parquet-файла (exp_exp_schema_tbl_777.parquet)
                  или маска (exp_exp_schema_tbl_*.parquet);
                  маска раскрывается самим скриптом
  schema          схема таблицы назначения
  table           таблица назначения
  batch_size      количество строк, через которое фиксируется вставка
                  (COMMIT после каждой порции), по умолчанию 10 000

Опции:

  --order-by      поле(я) сортировки перед вставкой, например "rrrr_key"
                  или "rrr_id, rrrr_key"; пусто — не сортировать
  --where         условие фильтрации (SQL DuckDB), например
                  --where "rrrr_name='7777777777'"; пусто — без фильтра
  --limit N       загрузить не более N строк (для проверки)
  --truncate      очистить таблицу назначения перед загрузкой
  --dry-run       показать план и выйти, ничего не загружая
  --synchronous-commit on|off
                  synchronous_commit на время загрузки, по умолчанию off
                  (быстрее; при падении сервера последние коммиты могут
                  потеряться)
  --env-file      файл с параметрами подключения
  --resume-file   файл-отчёт (по умолчанию <каталог скрипта>/parq_exp_resume.txt)
  --temp-dir      каталог для временных CSV
  --keep-temp     не удалять временный CSV
  --quiet         только итог


ПРИМЕРЫ
-------

    # один файл
    ./gp_from_parquet.py exp_exp_schema_tbl_777.parquet exp_schema tbl

    # все файлы по маске, сортировка, батч 50 000 строк
    ./gp_from_parquet.py "exp_exp_schema_tbl_*.parquet" exp_schema tbl 50000 \
        --order-by rrrr_key

    # с фильтром
    ./gp_from_parquet.py "exp_*.parquet" exp_schema tbl 10000 \
        --where "rrrr_name='7777777777'"

    # посмотреть план, ничего не загружая
    ./gp_from_parquet.py "exp_*.parquet" exp_schema tbl --dry-run


ФАЙЛ-ОТЧЁТ parq_exp_resume.txt
------------------------------
Создаётся в каталоге скрипта, записи дописываются блоками (история запусков).
Для каждого запуска фиксируется:

  * время запуска и завершения;
  * команда, источник, число файлов, таблица, размер батча;
  * условия сортировки и фильтрации;
  * статус: УСПЕШНО / ОШИБКА / НЕТ ДАННЫХ / ОТМЕНЕНО;
  * сколько строк загружено и сколько было в источнике;
  * сколько батчей выполнено;
  * время выполнения, время загрузки (COPY+COMMIT), время подготовки;
  * список файлов;
  * текст ошибки, если что-то пошло не так.

Пример блока:

  ================================================================================
  Запуск:           2026-10-30 12:23:05
  Завершение:       2026-10-30 12:23:56
  Команда:          ./gp_from_parquet.py exp_..._444.parquet wrk_san t 5000 --order-by rrrr_key
  Источник:         exp_exp_schema_tbl_444.parquet
  Файлов:           1
  Таблица:          wrk_san.gp_from_parquet_test
  Размер батча:     5 000
  Сортировка:       rrrr_key
  Фильтр:           нет
  Статус:           УСПЕШНО
  Строк загружено:  21 702
  Батчей:           5 из 5
  Время выполнения: 50.9 c
  Время загрузки:   28.8 c
  Подготовка:       0.0 c

  Файлы:
    exp_exp_schema_tbl_444.parquet (916.2 KB)


КАК ЭТО УСТРОЕНО (ПОЧЕМУ БЫСТРО)
---------------------------------
  1. DuckDB читает parquet, применяет WHERE и сортировку и ОДИН РАЗ
     материализует результат во временную таблицу с номером строки
     __gp_load_rn — дальше нарезка на порции идёт без повторной сортировки
     и без медленного OFFSET.
  2. Каждая порция выгружается нативным writer'ом DuckDB в CSV и сразу
     заливается в Greenplum через COPY ... FROM STDIN WITH CSV — самый
     быстрый штатный способ вставки.
  3. После каждой порции выполняется COMMIT (размер порции = batch_size).
  4. synchronous_commit=off на время сессии (можно вернуть on).
  5. Колонки parquet сопоставляются с колонками таблицы по имени без учёта
     регистра (проверено на таблице с "rrrr_key" в верхнем регистре).
     Если в parquet есть колонка, которой нет в таблице — скрипт
     останавливается с понятной ошибкой. Если в таблице есть колонки,
     которых нет в parquet, они получают значения по умолчанию / NULL.


ПРОВЕРКИ НА РЕАЛЬНЫХ ДАННЫХ
----------------------------
  * exp_exp_schema_tbl_444.parquet (21 702 строки) — контрольная
    сверка с parquet: count, count(distinct), суммы, min/max timestamp,
    длина текста, число NULL — полностью совпали.
  * Маска exp_exp_schema_tbl_4*.parquet + --truncate +
    --where "rrr_id = 444" — 21 702 строки, только rrr_id=444.
  * --order-by, --limit 20000, --dry-run — работают.
  * Ошибки: нет таблицы, нет колонок в таблице, слишком длинное значение
    при COPY, неверный тип в --where — все дают понятное сообщение
    и попадают в отчёт.

Замечание: частично загруженные батчи при ошибке остаются закоммиченными
(каждый батч фиксируется отдельно) — это ожидаемое поведение.


НЮАНСЫ GREENPLUM, КОТОРЫЕ УЧТЕНЫ
---------------------------------
  * Обязателен gssencmode=disable (иначе "invalid response to GSSAPI
    negotiation").
  * GP 5.28 не понимает новый синтаксис COPY ... WITH (FORMAT csv) —
    используется старый WITH CSV NULL AS '\N'.
  * Если колонка строковая, значение в --where надо брать в кавычки:
    --where "rrrr_name='7777777777'". На попытку сравнить varchar с числом
    скрипт печатает подсказку.
  * --truncate выполняется до загрузки и фиксируется сразу: если загрузка
    потом упадёт, таблица останется с частичными данными (уже загруженные
    батчи закоммичены).
  * --where и --order-by — это SQL-выражения для DuckDB.


ЗАВИСИМОСТИ
-----------
  Python 3, psycopg2-binary, duckdb. PyArrow не требуется.
  Параметры подключения читаются из .env.secret_db (блок GP_IN_*:
  GP_IN_HOST, GP_IN_PORT, GP_IN_DB, GP_IN_USER, GP_IN_PASSWORD,
  опционально GP_IN_SSLMODE, GP_IN_GSSENCMODE).
