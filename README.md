# Database Migration via Parquet

Небольшой pet-проект для переливки данных между тестовыми базами данных, когда прямой линк между ними отсутствует и создать его нельзя.

## 🎯 Цель проекта

Перенести данные из одной тестовой БД в другую тестовую БД через промежуточный файл формата **Parquet**. Поскольку прямой связи между базами нет, данные выгружаются в файл, а затем загружаются из него в целевую базу.

Изначально проект писался под **Greenplum**, но так как в основе лежит универсальный промежуточный формат (Parquet), скрипты легко адаптировать под другие СУБД.

## 💡 Идея и потенциал развития

Схема «источник → Parquet → приёмник» универсальна. Например, можно:

- выгрузить данные из **MSSQL Server** в Parquet,
- а затем загрузить этот файл в **Greenplum**.

Это открывает пространство для развития проекта: добавление новых коннекторов к разным СУБД и расширение поддерживаемых сценариев миграции.

## 🧩 Текущее ограничение

При переносе между разными СУБД **необходимо учитывать различия в типах данных**. Один и тот же тип в источнике и приёмнике может называться и вести себя по-разному (например, `DATETIME` в MSSQL и `TIMESTAMP` в Greenplum, или разная точность числовых типов).

Поэтому при подключении новой СУБД потребуется:

- описать маппинг типов «источник → Parquet → приёмник»;
- при необходимости написать скрипт преобразования данных из типа конкретной БД в эквивалентный тип другой БД.

Это ключевая точка роста проекта.

## 🛠️ Как это работает

```
[Source DB] --(extract)--> [Parquet file] --(load)--> [Target DB]
```

1. **Extract** — данные выгружаются из исходной БД в Parquet.
2. **Store** — Parquet-файл выступает промежуточным звеном (не требует живого соединения между БД).
3. **Load** — данные загружаются из Parquet в целевую БД.

## 🤖 О скриптах

Скрипты написаны с помощью ИИ (AI-assisted development) и ориентированы на практическую задачу — перенос данных между тестовыми средами. Проект задуман как учебный/pet: цель была поработать с Greenplum и проверить подход через промежуточный Parquet.
